# DataCortex-AI Comprehensive Results and Comparisons

This document summarizes reproducible local evidence. It does not claim production certification or external leaderboard superiority.

## Executive Results

- Fixture benchmark coverage: 7 completed datasets with recorded integrity status.
- Mean recorded fixture score: 0.904; metric is dataset-specific and not averaged for leaderboard use.
- Executable model comparisons: 6 datasets compared across dummy, linear, tree, boosting, DataCortex, and broad-pool groups.
- Baseline sanity comparisons: 6 local CSV fixtures compared against deterministic dummy predictors.
- Mean absolute lift over dummy sanity baselines: 0.396.
- Failure-mode checks summarized: 6 risks mapped to tests or E2E artifacts.
- Static code-safety attack set: recorded 100% block rate for scripted AST-screened attacks.
- Test-suite evidence: 74 passing tests recorded in validation notes.

## Concrete Novelty Mechanisms

| Novelty | Concrete Mechanism | Benchmark / Validation Signal |
| --- | --- | --- |
| Fingerprint-bounded model budget | Data fingerprint selects supported candidate families before training. | comparative_benchmarks_summary.csv records model budget ratio and broad-pool gap. |
| Task-aware market-basket routing | Sparse item-slot data suppresses target inference and supervised modeling. | Kaggle Groceries E2E preserves 9,835/9,835 rows and 2,824 repeated baskets. |
| Integrity-aware lifecycle | Pre/post mutation fingerprints surface row, sparsity, and target drift. | VALIDATION_RESULTS.md records integrity status per completed dataset. |
| Pre-execution code safety gate | AST validation rejects unsafe generated Python before execution. | Scripted attack set records 100% block rate for covered unsafe patterns. |
| Observable long-running execution | Phase events and checkpoints expose active pipeline state. | demo_events.json and checkpoint artifacts are persisted by demo runs. |

## Failure-Mode Validation

These checks target concrete regressions discovered while hardening the project, especially the store/groceries dataset failure where the UI showed a long modeling phase and all candidate models errored.

| Risk | Validation | Expected Behavior | Artifact | Status |
| --- | --- | --- | --- | --- |
| Sparse market-basket CSV misread as supervised classification | Kaggle Groceries E2E and ingestion target-detection tests | Detect market_basket, suppress automatic target selection, skip supervised training without explicit target | demo_outputs/kaggle_groceries_iter4/demo_summary.json | pass |
| Duplicate basket rows removed as ordinary duplicates | Kaggle Groceries E2E duplicate-frequency check | Retain 9,835/9,835 rows and preserve 2,824 repeated basket rows as frequency signal | demo_outputs/kaggle_groceries_iter4/demo_report.md | pass |
| Generated code performs unsafe imports, dynamic execution, or filesystem mutation | Scripted AST attack suite | Reject prohibited imports, eval/exec, networking modules, file mutation, and dunder traversal before execution | tests/test_code_validator.py | pass |
| Long-running modeling appears frozen to the user | Planner/demo event stream and checkpoint artifacts | Emit phase, plan, integrity, and completion events; persist checkpoint JSON for post-run inspection | demo_outputs/kaggle_titanic_iter3/demo_events.json | pass |
| Task detection selects an invalid target from structural item-slot columns | Target-detection regression tests | Require explicit target for supervised learning when structural market-basket pattern is detected | tests/test_ingestion_target_detection.py | pass |
| Validation reports overstate evidence quality | Evidence grading in this results package | Separate smoke tests, fixture benchmarks, E2E demos, baselines, and limitations | COMPREHENSIVE_RESULTS.md | pass |

## Evidence Limits

- Dummy baselines are sanity baselines, not competitive AutoML baselines.
- Some validation scores come from the repository validation report rather than rerunning a full hyperparameter benchmark in this script.
- Capability comparisons are mechanism comparisons based on documented project scope and common tool categories.
- Executable comparisons use local sklearn-style baselines; they do not substitute for a future benchmark against installed TPOT, AutoGluon, or auto-sklearn under equal time budgets.
- The strongest current claim is validated prototype behavior with reproducible local artifacts; production readiness remains unclaimed.
- Results should be updated whenever validation fixtures, model candidates, or demo datasets change.
